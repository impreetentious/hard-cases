# ADR-0019: The board has one entry point, and it is not the command line

## Context

The scoreboard is generated: `cargo run -p hc-bench --bin scoreboard` writes
`docs/scoreboard.md` from the committed corpora, and a test in the same crate
regenerates it and diffs, so a stale board fails the ordinary suite.

The workspace layout anticipated a second way in — a `hc bench` subcommand
wrapping the harness, which would make `hc-cli` depend on `hc-bench`. That edge
was written down before either side existed.

Two things about that edge are worth stating now that both do exist.

`hc-bench` holds the reference solver. It is the oracle: a dense textbook
tableau with Bland's rule that exists to disagree with the fast implementation,
and a gate refuses the build if it ever imports the production linear algebra.
Linking it into the shipped `hc` binary would put the oracle inside the program
it is an oracle for. Nothing would break — the ban runs the other way, and the
reference solver would still import nothing — but a reader auditing the trust
story would have to work that out, and the arrangement is the thing this
project asks people to audit.

The wrapper also adds no capability. It would run the same function the binary
runs, on the same corpora, writing the same file.

## Decision

**The board is generated by `hc-bench`'s own binary and by nothing else.**
`hc-cli` does not depend on `hc-bench`, and there is no `hc bench` subcommand.

`hc receipt` stays where it is: it measures the verifier and needs none of the
harness.

## Consequences

The `hc` binary contains the solver, the certificate machinery, and the
verifier, and nothing that exists to disagree with them. `cargo tree -p hc-cli`
shows a dependency list a reader can hold in their head.

Somebody wanting the board runs a `cargo run` line rather than a subcommand.
That is one more thing to know and it is written at the top of the generated
document, which is where a person looking at the board already is.

If a future surface genuinely needs the harness from inside the command line —
a `--against-reference` flag on `solve`, say — this record is what it has to
argue with, and the argument would be about that feature rather than about
tidiness.

**What an audit of this record found.** The edge described above as planned was
already built. `hc-cli` had declared `hc-bench` since v0.5.4 and called
`hc_bench::receipt::of` since v0.5.5 — seven versions before this record was
written — so `cargo tree -p hc-cli` carried the reference solver and, through
it, the tamper corpus, and the paragraph about what the `hc` binary contains
was not true of the built artifact on the day it was typed.

The cause was the sentence above about the receipt. It measures the verifier
and needs none of the harness, and it was living inside the harness anyway,
which is what the command line had to take to reach it. It is `hc-receipt`
now — its own crate, over the hash and nothing else — and `hc-cli` depends on
that instead. The forbidden-API scan refuses any crate that declares
`hc-bench`, so the edge is now closed by a gate rather than by this record,
which on its own turned out not to be enough.

## Alternatives considered

**Build the wrapper as planned.** Rejected for the two reasons above: it puts
the oracle in the audited binary and buys nothing.

**Move the reference solver out of `hc-bench` so the edge is harmless.** That
would be a third crate whose only purpose is to make a convenience subcommand
defensible, and the reference solver belongs beside the campaigns that use it.

## Supersedes / superseded by

Neither. It records a planned edge that was not built, and why.
